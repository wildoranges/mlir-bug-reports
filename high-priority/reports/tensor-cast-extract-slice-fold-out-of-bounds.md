# [fuzzer-found][mlir][tensor] tensor.cast canonicalization (TensorCastExtractSlice) folds a dynamic extract_slice into a statically out-of-bounds one (invalid IR)

## LLVM version and environment

- Commit: `0cae57720c3ca7cb09b5ba48d199f1ba04e3aae2` (2026-11-26)
- Build: `Release` with `LLVM_ENABLE_ASSERTIONS=ON`
- Platform: `x86_64` Linux

## Reproducer

`repro.mlir`:
```mlir
func.func @f(%t: tensor<4xf32>, %n: index) -> tensor<8xf32> {
  %e = tensor.extract_slice %t[2] [%n] [1] : tensor<4xf32> to tensor<?xf32>
  %c = tensor.cast %e : tensor<?xf32> to tensor<8xf32>
  return %c : tensor<8xf32>
}
```

Commands:
```console
$ mlir-opt repro.mlir -o /dev/null && echo verifies
$ mlir-opt repro.mlir --canonicalize
```


## Expected behaviour

The input is valid IR (and even if the cast would be UB when executed, the same slice + cast can sit inside an unreachable branch such as an `scf.if` whose condition is false at runtime). `--canonicalize` should not produce invalid IR; the `TensorCastExtractSlice` pattern should bail out when folding the cast's static size into `tensor.extract_slice` would make the slice statically out of bounds.

## Actual behaviour

`--canonicalize` folds the cast unconditionally and fails verification with an out-of-bounds slice error:

```console
$ mlir-opt repro.mlir -o /dev/null && echo verifies
verifies
$ mlir-opt repro.mlir --canonicalize
repro.mlir:3:8: error: slice along dimension 0 runs out-of-bounds: 9 >= 4
  %c = tensor.cast %e : tensor<?xf32> to tensor<8xf32>
       ^
repro.mlir:3:8: note: see current operation: %0 = "tensor.extract_slice"(%arg0) <{operandSegmentSizes = array<i32: 1, 0, 0, 0>, static_offsets = array<i64: 2>, static_sizes = array<i64: 8>, static_strides = array<i64: 1>}> : (tensor<4xf32>) -> tensor<8xf32>
```

**Verified observations:**

1. Sibling slice canonicalization patterns such as `ExtractSliceOpCastFolder` check whether the resulting static offsets/sizes/strides verify before rewriting (added in #132534):
   https://github.com/llvm/llvm-project/blob/0cae57720c3ca7cb09b5ba48d199f1ba04e3aae2/mlir/lib/Dialect/Tensor/IR/TensorOps.cpp#L2620-L2626
2. `TensorCastExtractSlice` copies the static sizes from the `tensor.cast` result type into the producing `tensor.extract_slice` without performing that bounds check:
   https://github.com/llvm/llvm-project/blob/0cae57720c3ca7cb09b5ba48d199f1ba04e3aae2/mlir/lib/Dialect/Tensor/IR/TensorOps.cpp#L527-L566

**Possible fix direction (hypothesis):**

Guard `TensorCastExtractSlice` with the same static bounds check used by `ExtractSliceOpCastFolder` (bailing out if the rewritten `extract_slice` would fail verification).
