# [fuzzer-found][mlir][tensor] tensor.cast canonicalization (TensorCastExtractSlice) folds a dynamic extract_slice into a statically out-of-bounds one (invalid IR)

Since #130487, the `tensor.extract_slice` verifier rejects slices that are statically out of bounds. #132534 then made the slice canonicalization patterns that turn dynamic offsets or sizes into static ones bail out if the result would be out of bounds ("Pattern does not apply if the produced op would not verify"), e.g. `ExtractSliceOpCastFolder`:

https://github.com/llvm/llvm-project/blob/8445b527ed0da1f9156f27be8c193624d0292253/mlir/lib/Dialect/Tensor/IR/TensorOps.cpp#L2620-L2626

`TensorCastExtractSlice`, a `tensor.cast` canonicalization pattern, has no such check. It copies the static sizes of the cast's result type into the producing `extract_slice` and creates the new slice unconditionally:

https://github.com/llvm/llvm-project/blob/8445b527ed0da1f9156f27be8c193624d0292253/mlir/lib/Dialect/Tensor/IR/TensorOps.cpp#L527-L566

So a valid slice with a dynamic size becomes a statically out-of-bounds slice, and `--canonicalize` fails:

`repro.mlir`:
```mlir
func.func @f(%t: tensor<4xf32>, %n: index) -> tensor<8xf32> {
  %e = tensor.extract_slice %t[2] [%n] [1] : tensor<4xf32> to tensor<?xf32>
  %c = tensor.cast %e : tensor<?xf32> to tensor<8xf32>
  return %c : tensor<8xf32>
}
```

```console
$ mlir-opt repro.mlir -o /dev/null && echo verifies
verifies
$ mlir-opt repro.mlir --canonicalize
repro.mlir:3:8: error: slice along dimension 0 runs out-of-bounds: 9 >= 4
  %c = tensor.cast %e : tensor<?xf32> to tensor<8xf32>
       ^
repro.mlir:3:8: note: see current operation: %0 = "tensor.extract_slice"(%arg0) <{operandSegmentSizes = array<i32: 1, 0, 0, 0>, static_offsets = array<i64: 2>, static_sizes = array<i64: 8>, static_strides = array<i64: 1>}> : (tensor<4xf32>) -> tensor<8xf32>
```

This code would have UB if it ran, but it may be unreachable. The same error occurs when the slice and cast are inside the `then` branch of an `scf.if` whose condition is false at runtime.

**Version**: llvm-project main @ 8445b527ed0da1f9156f27be8c193624d0292253 (2026-11-16), Release + `LLVM_ENABLE_ASSERTIONS=ON`, x86_64 Linux.
