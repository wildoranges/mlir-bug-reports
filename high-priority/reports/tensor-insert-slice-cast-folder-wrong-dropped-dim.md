# [fuzzer-found][mlir][tensor] insert_slice canonicalization of a tensor.cast source changes which unit dim a rank-reducing insert drops (miscompile)

`InsertSliceOpCastFolder` (a `tensor.insert_slice` / `tensor.parallel_insert_slice` canonicalization) folds a `tensor.cast` on the source and replaces dynamic sizes with static sizes from the cast's source type. To decide which sizes correspond to source dimensions, it recomputes the rank-reduction mask from the cast source's shape with `matchDynamic=true`, instead of using the insert's own source type:

https://github.com/llvm/llvm-project/blob/8445b527ed0da1f9156f27be8c193624d0292253/mlir/lib/Dialect/Tensor/IR/TensorOps.cpp#L3100-L3123

If a dynamic size is 1 at runtime, the two masks can differ. In the reproducer, the insert has sizes `[1, %a, %b, 1]` and source type `tensor<?x?x1xf32>`, so the dropped destination dim is dim 0. The cast source is `tensor<1x3x1xf32>`; matched against `[1, ?, ?, 1]` with `matchDynamic=true`, it yields the mask {3}. The pattern therefore rewrites the sizes to `[1, 3, 1, 1]`, and the new insert drops dim 3 instead of dim 0. The data lands in dim 1 of the destination instead of dim 2:

`repro.mlir`:
```mlir
func.func @kernel(%s0: tensor<1x3x1xf32>, %d: tensor<1x4x4x1xf32>, %a: index, %b: index) -> tensor<1x4x4x1xf32> {
  %s = tensor.cast %s0 : tensor<1x3x1xf32> to tensor<?x?x1xf32>
  %r = tensor.insert_slice %s into %d[0, 0, 0, 0] [1, %a, %b, 1] [1, 1, 1, 1] : tensor<?x?x1xf32> into tensor<1x4x4x1xf32>
  return %r : tensor<1x4x4x1xf32>
}
func.func @main() {
  %s0 = arith.constant dense<[[[1.0], [2.0], [3.0]]]> : tensor<1x3x1xf32>
  %d = arith.constant dense<0.0> : tensor<1x4x4x1xf32>
  %a = arith.constant 1 : index
  %b = arith.constant 3 : index
  %r = call @kernel(%s0, %d, %a, %b) : (tensor<1x3x1xf32>, tensor<1x4x4x1xf32>, index, index) -> tensor<1x4x4x1xf32>
  %c0 = arith.constant 0 : index
  %c2 = arith.constant 2 : index
  %x = tensor.extract %r[%c0, %c0, %c2, %c0] : tensor<1x4x4x1xf32>
  %y = tensor.extract %r[%c0, %c2, %c0, %c0] : tensor<1x4x4x1xf32>
  vector.print %x : f32
  vector.print %y : f32
  return
}
```

```console
$ mlir-opt repro.mlir --canonicalize | grep insert_slice
    %inserted_slice = tensor.insert_slice %arg0 into %arg1[0, 0, 0, 0] [1, 3, 1, 1] [1, 1, 1, 1] : tensor<1x3x1xf32> into tensor<1x4x4x1xf32>
$ LOWER="--one-shot-bufferize=bufferize-function-boundaries --expand-strided-metadata --finalize-memref-to-llvm --lower-affine --convert-scf-to-cf --convert-to-llvm --reconcile-unrealized-casts"
$ RUN="mlir-runner -e main -entry-point-result=void -shared-libs=$LLVM_BUILD/lib/libmlir_c_runner_utils.so,$LLVM_BUILD/lib/libmlir_runner_utils.so"
$ mlir-opt repro.mlir $LOWER | $RUN
3
0
$ mlir-opt repro.mlir --canonicalize $LOWER | $RUN
0
3
```

(`$LLVM_BUILD` is the LLVM/MLIR build directory.) The input has no UB: at runtime the insert's sizes are `[1, 1, 3, 1]`, which match the `1x3x1` source after dropping the leading unit dim, and the slice is in bounds of `1x4x4x1`. The source element `[0, 2, 0]` (value 3.0) belongs at destination `[0, 0, 2, 0]`, so the expected output is `3` then `0`, which is what the program prints without `--canonicalize`. With the correct mask {0}, the substituted sizes would be `[1, 1, 3, 1]`.
