# [fuzzer-found][mlir][tensor] insert_slice canonicalization of a tensor.cast source changes which unit dim a rank-reducing insert drops (miscompile)

## LLVM version and environment

- Commit: `0cae57720c3ca7cb09b5ba48d199f1ba04e3aae2` (2026-11-26)
- Build: `Release` with `LLVM_ENABLE_ASSERTIONS=ON`
- Platform: `x86_64` Linux

## Reproducer

`repro.mlir`:
```mlir
func.func @kernel(%s0: tensor<1x3x1xf32>, %d: tensor<1x4x4x1xf32>, %a: index, %b: index) -> tensor<1x4x4x1xf32> {
  %s = tensor.cast %s0 : tensor<1x3x1xf32> to tensor<?x?x1xf32>
  %r = tensor.insert_slice %s into %d[0, 0, 0, 0] [1, %a, %b, 1] [1, 1, 1, 1] : tensor<?x?x1xf32> into tensor<1x4x4x1xf32>
  return %r : tensor<1x4x4x1xf32>
}
func.func @main() {
  %s0 = arith.constant dense<[[[1.0], [2.0], [3.0]]]> : tensor<1x3x1xf32>
  %d = arith.constant dense<0.0> : tensor<1x4x4x1xf32>
  %a = arith.constant 1 : index
  %b = arith.constant 3 : index
  %r = call @kernel(%s0, %d, %a, %b) : (tensor<1x3x1xf32>, tensor<1x4x4x1xf32>, index, index) -> tensor<1x4x4x1xf32>
  %c0 = arith.constant 0 : index
  %c2 = arith.constant 2 : index
  %x = tensor.extract %r[%c0, %c0, %c2, %c0] : tensor<1x4x4x1xf32>
  %y = tensor.extract %r[%c0, %c2, %c0, %c0] : tensor<1x4x4x1xf32>
  vector.print %x : f32
  vector.print %y : f32
  return
}
```

Commands (`$LLVM_BUILD` is the LLVM/MLIR build directory):

$ mlir-opt repro.mlir --canonicalize | grep insert_slice
$ LOWER="--one-shot-bufferize=bufferize-function-boundaries --expand-strided-metadata --finalize-memref-to-llvm --lower-affine --convert-scf-to-cf --convert-to-llvm --reconcile-unrealized-casts"
$ RUN="mlir-runner -e main -entry-point-result=void -shared-libs=$LLVM_BUILD/lib/libmlir_c_runner_utils.so,$LLVM_BUILD/lib/libmlir_runner_utils.so"

## Expected behaviour

The input verifies and has no UB: at runtime the insert sizes are `[1, 1, 3, 1]`, which match the `1x3x1` source after dropping the leading unit dimension (dim 0), and the slice is in bounds of `1x4x4x1`. Source element `[0, 2, 0]` (value `3.0`) belongs at destination `[0, 0, 2, 0]`, while `[0, 2, 0, 0]` stays `0.0`.

Both the uncanonicalized and `--canonicalize` runs should print:
```text
3
0
```
And the folded `tensor.insert_slice` should preserve the dropped dimension (dim 0), giving sizes `[1, 1, 3, 1]`.

## Actual behaviour

`--canonicalize` folds the `tensor.insert_slice` sizes to `[1, 3, 1, 1]`, switching the dropped unit dimension from dim 0 to dim 3 so the data lands in dim 1 instead of dim 2:

```console
$ mlir-opt repro.mlir --canonicalize | grep insert_slice
    %inserted_slice = tensor.insert_slice %arg0 into %arg1[0, 0, 0, 0] [1, 3, 1, 1] [1, 1, 1, 1] : tensor<1x3x1xf32> into tensor<1x4x4x1xf32>
$ mlir-opt repro.mlir $LOWER | $RUN
3
0
$ mlir-opt repro.mlir --canonicalize $LOWER | $RUN
0
3
```

## Analysis and possible fix (optional)

<details>
<summary> Click to expand ... </summary>

**Verified observation:**

`InsertSliceOpCastFolder` (shared by `tensor.insert_slice` and `tensor.parallel_insert_slice`) folds a `tensor.cast` on the source and substitutes static sizes from the cast's source type into the dynamic size positions:

https://github.com/llvm/llvm-project/blob/0cae57720c3ca7cb09b5ba48d199f1ba04e3aae2/mlir/lib/Dialect/Tensor/IR/TensorOps.cpp#L3100-L3123

To determine which sizes correspond to source dimensions, it computes `computeRankReductionMask(insertSliceOp.getStaticSizes(), srcType.getShape(), /*matchDynamic=*/true)` using `srcType` (the cast's source type) instead of the original insert's source type (`insertSliceOp.getSourceType()`).

When a dynamic size becomes `1` in `srcType`, the two masks can differ:
- On the original insert, sizes are `[1, ?, ?, 1]` and the insert's source type is `tensor<?x?x1xf32>`, so the dropped destination dimension is dim 0 (`{0}`).
- Matching `[1, ?, ?, 1]` against the cast source `tensor<1x3x1xf32>` with `matchDynamic=true` yields `{3}` instead, so the pattern substitutes sizes as `[1, 3, 1, 1]` and drops dim 3.

**Possible fix direction (hypothesis):**

Compute the dropped-dimension mask from the original `insertSliceOp.getSourceType()` (e.g., `insertSliceOp.getDroppedDims()`) rather than recomputing it from the cast's source type, and use that mask when mapping `srcType` dimensions onto `mixedSizes`.

</details>
