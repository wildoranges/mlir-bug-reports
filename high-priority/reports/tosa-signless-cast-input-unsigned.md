# [fuzzer-found][mlir][tosa] tosa-convert-integer-type-to-signless drops unsignedness of tosa.cast inputs (input_unsigned is not set) -> wrong values

`tosa-convert-integer-type-to-signless` rewrites `ui8`/`si8`/... tensors to signless ones. Its own description says the signedness must then be carried by the operations, as `tosa.rescale` does with `input_unsigned`/`output_unsigned`:
https://github.com/llvm/llvm-project/blob/8445b527ed0da1f9156f27be8c193624d0292253/mlir/lib/Dialect/Tosa/Transforms/TosaConvertIntegerTypeToSignless.cpp#L13-L31

Since #215838, `tosa.cast` has an `input_unsigned` attribute, and the TOSA-to-Linalg lowering uses it to read an integer input as unsigned:
https://github.com/llvm/llvm-project/blob/8445b527ed0da1f9156f27be8c193624d0292253/mlir/lib/Conversion/TosaToLinalg/TosaToLinalg.cpp#L592-L593

The generic conversion pattern in the signless pass copies the operation's properties unchanged, so a `tosa.cast` from `ui8` becomes a cast from signless `i8` with `input_unsigned = false`:
https://github.com/llvm/llvm-project/blob/8445b527ed0da1f9156f27be8c193624d0292253/mlir/lib/Dialect/Tosa/Transforms/TosaConvertIntegerTypeToSignless.cpp#L66-L104

`cast.mlir`:
```mlir
func.func @g(%u: tensor<2xui8>) -> tensor<2xf32> {
  %r = tosa.cast %u : (tensor<2xui8>) -> tensor<2xf32>
  return %r : tensor<2xf32>
}
```

```console
$ mlir-opt cast.mlir --pass-pipeline="builtin.module(func.func(tosa-convert-integer-type-to-signless))" | grep tosa.cast
    %0 = tosa.cast %arg0  : (tensor<2xi8>) -> tensor<2xf32>
```

End to end, the unsigned value 200 is converted to -56.0:

`run.mlir`:
```mlir
func.func @main() {
  %u = "tosa.const"() <{values = dense<[200, 1]> : tensor<2xui8>}> : () -> tensor<2xui8>
  %r = tosa.cast %u : (tensor<2xui8>) -> tensor<2xf32>
  %i = arith.constant 0 : index
  %v = tensor.extract %r[%i] : tensor<2xf32>
  vector.print %v : f32
  return
}
```
