# [fuzzer-found][mlir][tosa] tosa-convert-integer-type-to-signless drops unsignedness of tosa.cast inputs (input_unsigned is not set) -> wrong values

## LLVM version and environment

- Commit: `0cae57720c3ca7cb09b5ba48d199f1ba04e3aae2` (2026-11-26)
- Build: `Release` with `LLVM_ENABLE_ASSERTIONS=ON`
- Platform: `x86_64` Linux

```mlir
func.func @g(%u: tensor<2xui8>) -> tensor<2xf32> {
  %r = tosa.cast %u : (tensor<2xui8>) -> tensor<2xf32>
```

## Expected behaviour

When converting `tensor<2xui8>` to signless `tensor<2xi8>`, `tosa.cast` should preserve input unsignedness (setting `input_unsigned = true`) so that downstream lowerings (`tosa-to-linalg`) interpret `200 : ui8` as unsigned and `run.mlir` prints `200`.

## Actual behaviour

`tosa-convert-integer-type-to-signless` drops the `ui8` unsignedness without setting `input_unsigned`, so `200 : ui8` is sign-extended and converted to `-56`:

```console
$ mlir-opt cast.mlir --pass-pipeline="builtin.module(func.func(tosa-convert-integer-type-to-signless))" | grep tosa.cast
    %0 = tosa.cast %arg0  : (tensor<2xi8>) -> tensor<2xf32>
$ mlir-opt run.mlir --pass-pipeline="$LOWER" | $RUN
-56
```

**Verified observations:**

1. `tosa-convert-integer-type-to-signless` rewrites signed/unsigned integer tensors (`si*`/`ui*`) to signless `i*` tensors; its file header notes that signedness must then be carried by operation attributes (as `tosa.rescale` does with `input_unsigned`/`output_unsigned`):
   https://github.com/llvm/llvm-project/blob/0cae57720c3ca7cb09b5ba48d199f1ba04e3aae2/mlir/lib/Dialect/Tosa/Transforms/TosaConvertIntegerTypeToSignless.cpp#L13-L31
2. `TosaToLinalg` checks `tosa.cast`'s `input_unsigned` attribute (added in #215838) to decide whether to treat the integer operand as unsigned:
   https://github.com/llvm/llvm-project/blob/0cae57720c3ca7cb09b5ba48d199f1ba04e3aae2/mlir/lib/Conversion/TosaToLinalg/TosaToLinalg.cpp#L592-L593
3. The generic conversion pattern in `TosaConvertIntegerTypeToSignless.cpp` copies properties unchanged without setting `input_unsigned = true` on `tosa.cast` when the original input element type is unsigned:
   https://github.com/llvm/llvm-project/blob/0cae57720c3ca7cb09b5ba48d199f1ba04e3aae2/mlir/lib/Dialect/Tosa/Transforms/TosaConvertIntegerTypeToSignless.cpp#L66-L104

**Possible fix direction (hypothesis):**

Handle `tosa::CastOp` explicitly (or adjust its `input_unsigned` property in the conversion pattern) so that unsigned integer inputs set `input_unsigned = true` when converted to signless types.
