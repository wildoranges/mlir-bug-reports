# [fuzzer-found][mlir][SPIR-V] ConvertSelectionOpToSelect erases a selection with live results (assertion failure in eraseOp)

Since #238896, the SPIRVToLLVM `SelectionPattern` treats a `spirv.mlir.selection` header as an ordinary block: zero or more non-terminator ops followed by a terminator, preserving preceding header ops when the region is inlined. The separate `ConvertSelectionOpToSelect` canonicalization (below) still requires, through its `onlyContainsBranchConditionalOp` helper, exactly one op, a `spirv.BranchConditional`. That assumption can only suppress this optional fold for multi-op headers; on this reproducer the header does satisfy it, so the helper is not where the failure occurs.

https://github.com/llvm/llvm-project/blob/8445b527ed0da1f9156f27be8c193624d0292253/mlir/lib/Dialect/SPIRV/IR/SPIRVCanonicalization.cpp#L1255-L1338

After matching, `matchAndRewrite` builds the `spirv.Select`/`spirv.Store` replacement and erases the original selection without checking that its results are unused. In the reproducer the selection yields a merge-block argument and `%r` is used by `arith.addi`; erasing the selection therefore trips `assert(op->use_empty())` in `PatternMatch.cpp:156`. The missing result/use check, not the header-shape precondition, is the crash.

`repro.mlir`:
```mlir
func.func @f(%cond: i1, %p: !spirv.ptr<i32, Function>, %a: i32, %b: i32) {
  %r = spirv.mlir.selection -> i32 {
    spirv.BranchConditional %cond, ^true, ^false
  ^true:
    spirv.Store "Function" %p, %a : i32
    spirv.Branch ^merge(%a : i32)
  ^false:
    spirv.Store "Function" %p, %b : i32
    spirv.Branch ^merge(%b : i32)
  ^merge(%m: i32):
    spirv.mlir.merge %m : i32
  }
  %s = arith.addi %r, %r : i32
  return
}
```
