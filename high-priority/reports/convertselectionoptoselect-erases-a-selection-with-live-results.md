# [fuzzer-found][mlir][SPIR-V] ConvertSelectionOpToSelect erases a selection with live results (assertion failure in eraseOp)

## LLVM version and environment

- Commit: `0cae57720c3ca7cb09b5ba48d199f1ba04e3aae2` (2026-11-26)
- Build: `Release` with `LLVM_ENABLE_ASSERTIONS=ON`
- Platform: `x86_64` Linux

## Reproducer

`repro.mlir`:
```mlir
func.func @f(%cond: i1, %p: !spirv.ptr<i32, Function>, %a: i32, %b: i32) {
  %r = spirv.mlir.selection -> i32 {
    spirv.BranchConditional %cond, ^true, ^false
  ^true:
    spirv.Store "Function" %p, %a : i32
    spirv.Branch ^merge(%a : i32)
  ^false:
    spirv.Store "Function" %p, %b : i32
    spirv.Branch ^merge(%b : i32)
  ^merge(%m: i32):
    spirv.mlir.merge %m : i32
  }
  %s = arith.addi %r, %r : i32
  return
}
```

Commands:
```console
$ mlir-opt repro.mlir -o /dev/null && echo verifies
$ mlir-opt repro.mlir --canonicalize
```


## Expected behaviour

The input is valid IR (`spirv.mlir.selection` yields an `i32` result used by `arith.addi`). `--canonicalize` should not crash; `ConvertSelectionOpToSelect` should either bail out when the `spirv.mlir.selection` has results (or uses), or replace its results rather than erasing a live operation.

## Actual behaviour

`mlir-opt --canonicalize` crashes with an assertion failure in `RewriterBase::eraseOp`:

## Analysis and possible fix (optional)

<details>
<summary> Click to expand ... </summary>

**Verified observation:**

`ConvertSelectionOpToSelect::matchAndRewrite` matches a 4-block `spirv.mlir.selection` whose `true` and `false` blocks each contain a `spirv.Store` + `spirv.Branch` to the merge block, emits a `spirv.Select` + `spirv.Store`, and unconditionally calls `rewriter.eraseOp(op)` without checking that the `spirv.mlir.selection` produces no results (or has no uses):

https://github.com/llvm/llvm-project/blob/0cae57720c3ca7cb09b5ba48d199f1ba04e3aae2/mlir/lib/Dialect/SPIRV/IR/SPIRVCanonicalization.cpp#L1255-L1339

When the merge block takes a block argument and yields it via `spirv.mlir.merge`, `%r` is live at `arith.addi`, tripping `assert(op->use_empty())` in `RewriterBase::eraseOp`.

**Possible fix direction (hypothesis):**

Check `if (selectionOp->getNumResults() > 0)` (or `!selectionOp->use_empty()`) and return `failure()` in `ConvertSelectionOpToSelect::matchAndRewrite` (or also check `mergeBlock->getNumArguments() == 0`).

</details>
